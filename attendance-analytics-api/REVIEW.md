# REVIEW.md

Review of the starter `app/main.py`. Defects are grouped by the function they
live in. "How you'd notice it" gives a concrete input/symptom; "How I fixed it"
points at what the rewritten file does.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How I fixed it |
|---|---|---|---|---|
| 1 | module setup, line 22 | `MongoClient(...)` is created **without `tz_aware=True`**, so PyMongo returns **naive** datetimes. Combined with naive arithmetic below, every IST-based rule is computed in the wrong frame. | Read a seeded `punch_in` and compute late/overtime: results are off by the 5:30 IST offset. | Create the client with `tz_aware=True` and convert UTC↔IST explicitly in every rule. |
| 2 | `compute_late_minutes`, 33-37 | Timezone: it does `punch_in.replace(hour, minute)` to build `shift_start`, treating the punch instant's own (UTC/naive) clock as if it were IST. Shift start is defined in **IST**. | A 09:28 IST punch-in (stored `03:58Z`) is measured against `03:30`, not `09:30`. Late minutes are wrong for everyone. | Convert `punch_in` to IST, build `shift_start` in IST on the attendance date, subtract. |
| 3 | `compute_late_minutes`, 37 | Grace boundary: `return minutes if minutes > 10 else 0`. R2 is "strictly more than **10:00**", then floor minutes **since shift_start**. Using `minutes > 10` on an int means 10:00–10:59 late → `minutes==10` → not `>10` → returns 0. | Shift 09:30, punch 09:40:01 should give 10; starter gives 0. | Compare elapsed **seconds > 600**, then `elapsed // 60`. |
| 4 | `compute_work_hours`, 41 | Rounding: `round(...)` is banker's (half-to-even); R4/R8 require **half-up**. | A true 8.125 → `round` gives 8.12, spec wants 8.13. | `Decimal(seconds/3600).quantize(0.01, ROUND_HALF_UP)`. |
| 5 | `compute_overtime`, 46 | Builds `end` as tz-**aware** (`tzinfo=IST`) but `punch_out` is **naive** → `punch_out - end` raises `TypeError` → **500**. | Any punch-out hits a 500 (a 500 is an automatic fail). | Keep all instants aware; compute in a single consistent frame. |
| 6 | `compute_overtime`, 46 | Overnight: `end` is placed on `date_str` (the start day). For an overnight shift the shift **ends on the next calendar day** (R1). | EMP0005 (22:00–06:00): overtime comes out hugely negative/zero. | `end_day = date + 1` when the shift is overnight. |
| 7 | `compute_overtime`, 47 | Missing the **≥ 30 min** threshold (R3): returns `max(0, minutes)` for any positive value. | Sample 1 punches out 5 min after shift end → spec expects 0, starter returns 5. | Return minutes only when `minutes >= 30`, else 0. |
| 8 | `create_employee`, 79-80 | **Race / wrong mechanism**: check-then-insert (`find_one` then `insert_one`). Two concurrent creates of the same `emp_code` both pass the check → two inserts. Contract requires a DB **unique index**. | Fire two identical creates in parallel → both 201. | Unique index on `emp_code`; `insert_one` in a `try/except DuplicateKeyError` → 409. |
| 9 | `create_employee`, 82 | `created_at = datetime.now()` is naive **server-local** time, and is returned as a datetime. Contract: server UTC, returned as **epoch ms**. | `created_at` is wrong by the server's offset and the wrong JSON type. | `datetime.now(tz=UTC)` truncated to seconds; serialize to epoch ms. |
| 10 | `create_employee` / `EmployeeIn`, 53-60 | **No validation**: `emp_code`, `email`, shift-time formats are unconstrained and `shift_start != shift_end` is never checked. Invalid bodies that must be 422 are accepted. | `POST` with `emp_code:"abc"` or `shift_start==shift_end` → 201 instead of 422. | Pydantic patterns/lengths + a model validator for the shift rule. |
| 11 | `list_employees`, 93 | Pagination off-by-one: `skip = page * page_size`. `page` starts at 1, so page 1 skips the first page. | `?page=1` returns records 21–40. | `skip = (page - 1) * page_size`. |
| 12 | `list_employees`, 94 | `total = count_documents({})` ignores the `department` filter. R10: `total` reflects the filters. | `?department=Sales` returns `total` = whole collection. | Count with the same filter `q`. |
| 13 | `list_employees`, 95 | Not sorted; contract requires `emp_code` ascending. Also `page_size` has no max (100). | Order is arbitrary; `?page_size=100000` is accepted. | `.sort("emp_code", 1)`, `page_size` capped at 100 via `Query(le=100)`. |
| 14 | `punch_in`, 101-102 | Unknown employee → `emp` is `None`, then `emp["shift_start"]` raises → **500**. Should be **404**. | `punch-in` for a non-existent `emp_code` → 500. | `if emp is None: raise HTTPException(404, ...)`. |
| 15 | `punch_in`, 102-103 | `datetime.fromtimestamp(ms/1000)` is naive **local**; `d = ts.date()` is the local/UTC date, not the **IST** attendance date, and there is no overnight handling (R1). Also no truncation to whole seconds. | A punch near IST midnight, or any overnight shift, gets the wrong `date`. | `ms_to_dt` (UTC, truncated) + `attendance_date()` with the IST + overnight rule. |
| 16 | `punch_in`, 104-105 | **Race**: check-then-insert on `(emp_code, date)`. Two simultaneous punch-ins → two records (or an error), not "exactly one 201, rest 409". | Parallel identical punch-ins both succeed. | Unique compound index `(emp_code, date)` + `DuplicateKeyError` → 409. |
| 17 | `punch_in`, 66 / 100 | `status` is a free `str` defaulting to PRESENT; `ABSENT`/`LEAVE` are accepted here even though only PRESENT/WFH/ON_DUTY are allowed. | `punch-in` with `status:"LEAVE"` → 201. | A `PresenceStatus` enum → invalid values are 422. |
| 18 | `punch_in`, 119-121 | Response shape: returns `punch_in` as a datetime and adds an `id` field. Contract: instants are epoch ms and attendance records have **no id**. | Response JSON doesn't match the schema. | Single `record_to_api()` serializer (epoch ms, no `_id`/`id`). |
| 19 | `punch_in` / `PunchInIn`, 65 | `punched_at: Optional[int]` has no bounds; seconds-looking values, floats and out-of-range numbers are not rejected (422). | `punched_at: 1783312500` (seconds) is accepted and mis-interpreted. | `EpochMillis = StrictInt` with `ge=1e11, le=~2100`. |
| 20 | `list_attendance`, 144-147 | **Loads the whole filtered collection into memory** (`list(find(q))`), then sorts and slices in Python. Contract: must not load the collection; must be fast at 100k and index-backed. | At 100k docs the endpoint is slow and memory-heavy. | Push `.sort().skip().limit()` to MongoDB, backed by the `(date, emp_code)` index. |
| 21 | `list_attendance`, 145 | Sort is `date` desc only; contract is `date` desc **then `emp_code` asc**. | Rows with the same date come back in arbitrary order. | Compound sort `[("date",-1),("emp_code",1)]`. |
| 22 | `list_attendance`, 124-143 | `date_from > date_to` is not rejected (should be 422); `page_size` max not enforced; response returns raw datetimes + an `id`. | `?date_from=2026-02-01&date_to=2026-01-01` → 200 with empty list instead of 422. | Validate the range → 422; cap `page_size`; serialize with `record_to_api`. |
| 23 | `health`, 72-74 | Always returns `{"status":"ok"}` without touching MongoDB. Contract: 200 only if a ping succeeds, else **503**. | With Mongo down, `/health` still says ok, so the runner starts testing too early. | `db.command("ping")` in a try/except → 503 on failure. |
| 24 | whole file | **No indexes are created.** The contract requires all indexes at startup, idempotently; analytics/list must be index-backed. | `/admin/explain/...` shows COLLSCAN on 100k docs. | A `lifespan` hook that `create_index(...)`es everything idempotently. |

## Examined and judged NOT a defect

- **`load_dotenv()` precedence** (line 20): `python-dotenv` does **not** override variables already set in the real environment, so "real environment variables win" already holds. Kept it.
- **`IST = timezone(timedelta(hours=5, minutes=30))`** (line 25): correct — IST has no DST, so a fixed offset is right. Reused it.
- **`compute_work_hours` operand order** (`punch_out - punch_in`): correct given punch-out is always after punch-in (which we now enforce), so the result is non-negative. The only bug there was the rounding (#4).
- **201 status on `create_employee` / `punch_in`**: matches the contract; left as-is.
